## Describe the bug

With vLLM 0.28.0 on a single H100 80GB, `Qwen/Qwen1.5-MoE-A2.7B-Chat` (architecture `Qwen2MoeForCausalLM`, bf16, unquantised, TP=1) produces degenerate text under greedy decoding whenever `CompilationConfig.mode` resolves to `VLLM_COMPILE` (3), and coherent text whenever it resolves to `NONE` (0). Nothing else in the configuration was found to matter: turning CUDA graphs on or off, enabling or disabling vLLM's torch.compile cache, and setting `custom_ops=['all']` all left the result unchanged. The behaviour is reproducible (two consecutive `generate` calls in the same process gave identical tokens in every configuration, and the three separate compile-on processes of rows 1, 2 and 5 gave identical tokens on all 16 prompts), so this is not run-to-run noise.

### Things that were ruled out

- **CUDA graphs.** With compilation on, `cudagraph_mode` `FULL_AND_PIECEWISE` (51 PIECEWISE plus 51 FULL graphs captured) and `NONE` (capture skipped) gave token-identical output on all 16 prompts. With compilation off, `FULL` (51 FULL graphs captured) and `NONE` also gave token-identical output on all 16 prompts. So graph capture neither causes nor masks the difference.
- **Compile cache.** Rows 1, 2 and 6 ran with `VLLM_DISABLE_COMPILE_CACHE=1` (log: `vLLM's torch.compile cache is disabled.`). Row 5 ran with the cache enabled; it compiled fresh (`Compiling a graph for compile range (1, 16384) takes 6.36 s`, then `saved AOT compiled function to /root/.cache/vllm/torch_compile_cache/torch_aot_compile/7954b1e9.../rank_0_0/model`; no line about loading an existing artefact) and produced tokens identical to row 1 on all 16 prompts. `VLLM_DISABLE_COMPILE_CACHE` controls vLLM's own cache only; Inductor's FX-graph cache stays enabled in 0.28.0 and was not cleared between processes.
- **custom_ops.** Row 6 passed `custom_ops=['all']` (log: `Enabled custom fusions: norm_quant, act_quant`), still compiled (`Compiling a graph for compile range (1, 16384) takes 2.13 s`), and was still degenerate: 9 of 16 prompts end in a cycle, 0 of 16 match eager, prompt 0 identical to row 1.
- **Flakiness.** Two consecutive `llm.generate` calls on the same batch in the same process gave identical tokens in all six processes.
- **Plugins.** `VLLM_PLUGINS=""` was set for every run so that no general plugin from the environment was loaded. Each process checked after engine construction that `vllm.plugins.plugins_loaded` was True, `vllm.envs.VLLM_PLUGINS` was `['']`, the general plugin package installed in this environment was absent from `sys.modules`, and `FusedMoERouter.select_experts` still resolved to `vllm/model_executor/layers/fused_moe/router/fused_moe_router.py` from the installed vLLM.
- **Batch position.** With compilation off, the two copies of each prompt in the batch produced identical tokens (8 of 8 pairs). With compilation on, no pair agreed (0 of 8 in rows 1, 2, 5 and 6) and every pair already differed at the first generated token, although the outputs for each position were reproducible across the two repeats. bf16 kernels are not guaranteed to be batch-invariant, so an occasional token flip between two copies would not be remarkable; disagreement from the first token on all 8 pairs, while the uncompiled run agrees on all 8, is why I do not read the compiled output as merely a different but valid greedy continuation.

```python
import os
os.environ.setdefault("VLLM_ENABLE_V1_MULTIPROCESSING", "0")  # engine core in the same process

from vllm import LLM, SamplingParams, TokensPrompt

MODEL = "Qwen/Qwen1.5-MoE-A2.7B-Chat"
REVISION = "ec052fda178e241c7c443468d2fa1db6618996be"

SHORT = [
    "The verifier re-runs a sampled computation and compares hashes.",
    "Floating-point addition is not associative, so",
    "def fibonacci(n):",
    "In 1854 the",
]
LONG = [" ".join(["The verifier records the batch shape at every step and replays it later."] * k)
        for k in (3, 6, 9, 12)]
PROMPTS = [p for pair in zip(SHORT, LONG) for p in pair] * 2   # 16 prompts, 8 distinct, each twice


def cycle_period(tokens, tail=16, max_period=3):
    t = tokens[-tail:]
    for p in range(1, max_period + 1):
        if len(t) > p and all(t[i] == t[i + p] for i in range(len(t) - p)):
            return p
    return None


def run(compile_on: bool, graphs_on: bool):
    graph_mode = ("FULL_AND_PIECEWISE" if compile_on else "FULL") if graphs_on else "NONE"
    llm = LLM(
        model=MODEL, tensor_parallel_size=1, seed=0, max_model_len=2048,
        enable_prefix_caching=False, enforce_eager=False,
        compilation_config={"mode": 3 if compile_on else 0, "cudagraph_mode": graph_mode},
        revision=REVISION, tokenizer_revision=REVISION,
    )
    tok = llm.get_tokenizer()
    sp = SamplingParams(temperature=0.0, max_tokens=32, logprobs=5, ignore_eos=True)
    batch = [TokensPrompt(prompt_token_ids=tok.encode(p)) for p in PROMPTS]
    for repeat in range(2):
        outs = llm.generate(batch, sp, use_tqdm=False)
        for i, o in enumerate(outs):
            ids = list(o.outputs[0].token_ids)
            print(f"[{i:2d}] period={cycle_period(ids)} ids={ids}")
            print(f"     text={o.outputs[0].text!r}")


# One configuration per fresh process:
#   compile on, graphs on   -> run(True, True)    (row 1)
#   compile on, graphs off  -> run(True, False)   (row 2)
#   compile off, graphs on  -> run(False, True)   (row 3)
#   compile off, graphs off -> run(False, False)  (row 4)
```
